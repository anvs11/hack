## Роль и видение UI

При регистрации спрашивайте роль, но делайте **единый интерфейс с ролевыми профилями** (personas)

### Почему спрашивать роль — нужно

1. **Разные критические источники.** PR без «Ведомостей» и TG-каналов про GS Labs — слепой. GR без regulation.gov.ru и sozd.duma.gov.ru — бесполезен. Стартовый набор из 30–50 источников сильно разный.
2. **Разные стартовые фильтры и категории.** PR: репутация / конкуренты / тренды / упоминания GS Labs. GR: регуляторика / НПА / КИИ / ПД / льготы.
3. **Разные алерты.** PR: «негатив о GS Labs в ТАСС». GR: «ПП №1937 вступило в силу 01.09.2026 — переоцените карточку №23».
4. **Разные KPI, по которым вас будут оценивать.** PR: «скорость реакции на инфоповод». GR: «0 пропусков НПА в статусе принято».
5. **Кейсодатель явно сказал: разные роли, разные задачи.** Проигнорируете — чекпоинт дня 4 провалите.

### Почему НЕ делать разные интерфейсы — важно

1. **Хакатон = фокус.** Разные интерфейсы = двойной frontend, двойное тестирование, половина силы команды уйдёт на верстку.
2. **Рамка продукта должна быть единой.** Это *один* «интеллектуальный аналитический центр», не два продукта.
3. **В реальности роли пересекаются.** GR смотрит новости про ФАС против Apple, PR смотрит новости про льготы для ИТ. Жёсткое разделение убьёт полезность.
4. **Это избыточно.** Разные результаты можно подавать через **фильтры и конфигурацию**, а не через разные экраны.

### Что делать: ролевые профили в едином интерфейсе

```
При регистрации:
  email → пароль → [Ваша роль: PR-менеджер | GR-специалист | Руководитель | Другое]
                                                                    ↓
После регистрации:
  ┌─────────────────────────────────────────────────────────────────┐
  │  Единый дашборд                                                  │
  │                                                                   │
  │  Автоконфигурация под роль:                                       │
  │  • Стартовый набор источников (30–50)                             │
  │  • Стартовые категории и фильтры                                  │
  │  • Типовые алерты                                                  │
  │  • Рекомендованные шаблоны дайджестов                             │
  │                                                                   │
  │  Переключатель профиля в углу:                                    │
  │  [Сейчас: GR-специалист ▾]  → можно переключить в любой момент    │
  └─────────────────────────────────────────────────────────────────┘
```

**Что видит PR:** лента вверху — «негатив про GS Labs, ФАС против Apple, 72 млн подписчиков OK». **Что видит GR:** лента вверху — «ПП №1937 вступило в силу, проверочный лист РКН обновлён, законопроект о маркировке ИИ-контента». **Один продукт, одна кодовая база, разный стартовый опыт.**

### Как это показать на демо

Демо начинается со сценария «Новый сотрудник — первый день»:
1. Регистрация → выбирает «GR-специалист».
2. Система говорит: «Подгружаю 47 источников: regulation.gov.ru, sozd.duma.gov.ru, 12 TG-каналов, дайджесты ЭБР/ИРИ. Настраиваю категории. Готово».
3. Специалист видит очередь: 3 карточки с пометкой «критичное», среди них карточка №23 — **«Статус изменился: действует с 01.09.2026»**. Он кликает, видит историю, подтверждает переоценку — алерт ушёл директору.
4. **Переключатель в углу:** клик → «PR-менеджер» → лента меняется: вверху новости про ФАС и онлайн-кинотеатры.

Это и есть демонстрация «гибкого управления источниками и данными» из обязательных требований кейса, и заодно продаёт идею, что один продукт закрывает двух специалистов.

## Что это меняет в продуктовой рамке (обновления в пак)

### 1. Позиционирование (меняется)
**Было:** «экономим 3 часа в день на мониторинге»
**Стало:** **«Не пропускаете критичные НПА и точки роста для управленческих решений»**
— язык покупателя (директора), а не пользователя
— цена ошибки измерима (штрафы до 4 млрд ₽, уголовка, приостановка сервиса)
— две ценности: защита + возможность

### 2. Ценностное предложение (дополнить)
Для **GR/юриста**: «Ни одного пропущенного НПА в статусе 'принято/действует', автоматический трекинг стадий, алерты при смене статуса — как у юриста-стажёра, который работает 24/7».
Для **PR**: «Утренняя лента с саммари и приоритетами про GS Labs, конкурентов и репутацию — разбор за 15 минут вместо 3 часов».
Для **руководителя**: «Дайджест управленческих решений: риски + точки роста на этой неделе».

### 3. Ключевая фича, которой нет ни у кого
**Lifecycle-трекинг НПА** — карточка живёт со стадиями: проект → принят → действует с дата → архив. При смене стадии — автоматический алерт + переоценка (К2 меняется с 1 на 3). История изменений сохраняется. Этого нет ни у Медиалогии, ни у КонсультантПлюс, ни у Brand Analytics.

### 4. Что НЕ автоматизируем (важно для честности)
- Ранжирование по К1–К6/Н1–Н4 — **остаётся за специалистом**. Мы предлагаем предварительный балл + объяснение «почему», но финал за человеком.
- Это не слабость — это правильное разделение: ИИ не пропускает, не устаёт, работает 24/7; человек принимает решение.

## ИДЕИ ПО ФИЧАМ 

### 1. Группировка похожих новостей в кластер с резюме ✅ → **MVP, но не как фича, а как гигиена**
Это не «фича» — это требование куратора: *«дубли одной новости схлопнуты в одну карточку»*. Но можно усилить:
- **Не просто дедуп**, а **тематический кластер**: 15 публикаций про один законопроект → одна карточка «Законопроект № 1286413-8 о страховых взносах» с агрегированным саммари.
- **Источник-лидер**: внутри кластера показываем самый авторитетный источник (regulation.gov.ru > Коммерсантъ > TG-канал).
- **Хронология развития темы**: «01.07 внесён → 15.07 первое чтение → 20.08 принят».

Это прямо закрывает H4 (доверие к саммари) и снижает когнитивную нагрузку — утренний разбор реально укладывается в 10–15 минут.

### 2. Детекция фейков / противоречивой информации ⚠️ → **Roadmap, не MVP**
Идея сильная, но для GS Labs это **не главная боль**. Их риск — не «Фейк про нас в жёлтой газете», а «Пропустили ПП № 1937 и потеряли статус в реестре ПО». Фейк-детекция — это PR-контур, вторая очередь.

**Но** есть версия, которая влезает в MVP и работает на основную ценность:
- **Автопроверка фактов саммари против оригинала** (AI1 в наших гипотезах) — это уже есть.
- **Флаг «противоречие с другим источником»**: если regulation.gov.ru говорит «принят 01.09», а Коммерсантъ — «перенесли на 01.12», система помечает и алертит GR. Это про **риск дезинформации в регуляторике**, а не про медиафейки. Вот это MVP.

### 3. Динамика и тренды ✅✅ → **MVP, ключевая фича для демо**
Это **самая сильная** из ваших идей, потому что она работает на нашу главую ценность — lifecycle НПА. Конкретные реализации:

**а) Timeline карточки НПА** (обязательно для демо!)
```
Карточка №23 (ПП №1937 о реестре ПО):
[Проект · 28.11.25] → [Принят · 01.03.26] → [Действует · 01.09.26 ← ВЫ ЗДЕСЬ]
                                                    ↑
                                        Следующий этап: 01.01.27 (серверное ПО)
```
Это именно то, чего нет в Excel (там версия файла датой, а история стадий теряется).

**б) «Нарастание давления» по теме**
- График количества упоминаний темы за 30 дней
- Автоматический флаг: «Резкий рост обсуждения ФАС + Apple за неделю» = сигнал GR
- Это закрывает кейс №33 в их реестре (штраф до 4 млрд ₽) — система могла бы предупредить о нарастании давления заранее

**в) Sentiment-динамика по продуктам GS Labs**
- График тональности упоминаний «Триколор» / «GS Group» за месяц
- Автоматическая корреляция: «Падение тональности 15.08 совпало с публикацией в Ведомостях о техсборе»

### 4. Анализ комментариев под постами ⚠️ → **Roadmap, вторая очередь**
Для GR-ядра (НПА) комментариев почти нет — регуляторные документы обсуждают в узких TG-каналах, не в комментах. Для PR-контура — да, полезно, но это вторая очередь после НПА.

**Исключение**: если в тестовом датасете будут посты в TG-каналах типа «ЦИПР-новости» с живым обсуждением — можно сделать **sentiment sampling** (не все комменты, а срез) как дополнение к саммари. Но это не MVP.

## Мои добавки: фичи, вытекающие из JTBD

### 5. **«Что это значит для GS Labs»** — автоматическая привязка НПА к продуктам компании 🔥 (MVP)
Это **killer-фича**, которой нет ни у одного конкурента:
- Карточка №23 (реестр ПО) → автоматически помечает: «Затрагивает: Триколор, серверное ПО, ЦОД»
- Карточка №22 (КИИ в связи) → «Затрагивает: инфраструктура связи GS Group»
- Карточка №33 (ФАС vs Apple) → «Затрагивает: DRM-системы, CAS»

**Как сделать на хакатоне:** в системе знаний держим список продуктов GS Labs (Триколор, серверное ПО, ресиверы, DRM и т.д.) + ключевые слова. LLM при обработке НПА сопоставляет с этим списком и выдаёт: `затронутые_продукты: ["Триколор", "CAS/DRM"]`.

Это прямо продаёт пилот: руководитель видит не абстрактный НПА, а «этот акт ударит по нашему основному продукту».

### 6. **Actionable recommendations** — не просто «что произошло», а «что делать» 🔥 (MVP)
Вместо сухого саммари — блок «Рекомендуемые действия»:
```
ПП №1937 вступает в силу 01.09.2026
✅ Что сделать:
  • Проверить совместимость серверного ПО с Astra Linux и RED OS
  • Обновить сведения в реестре до 01.06.2027
  • Подготовить маркировку "доверенное ПО" для закупок 44-ФЗ
📅 Срок: 30 дней
👤 Ответственный: [назначить]
```
Это закрывает **большую работу** (AJTBD): не «знать», а «действовать».

### 7. **Матрица рисков** — heatmap «продукты × регуляторные угрозы» (Demo Day wow-эффект)
Один экран для руководителя:
```
              | КИИ  | Реестр ПО | ПД   | Платф.эк. | ИИ-закон
Триколор      |  🟥  |    🟨     |  🟩  |    🟩     |   🟨
Серверное ПО  |  🟩  |    🟥     |  🟩  |    🟩     |   🟩
DRM-системы   |  🟨  |    🟩     |  🟩  |    🟥     |   🟩
```
Красные ячейки = есть активный НПА в статусе «действует» с высоким индексом. Это **визуализация всей работы GR-отдела на одном экране** — именно то, за что платит директор.

### 8. **Алерты-триггеры** (MVP, критично)
Не только «появилась новость», но и:
- «Прошло 30 дней с принятия НПА — пора действовать» (по К6)
- «Стадия изменилась: Проект → Принят» (lifecycle)
- «Похожий НПА принят в ЕС — ожидаем аналог в РФ через 6–12 мес» (опережающий сигнал)
- «Конкурент публично отреагировал на этот НПА» (сигнал GR)

### 9. **«Мостик в прошлое» — экспорт в Excel формата GS Labs** (MVP, обязательно)
Кнопка «Экспорт реестра (формат GS Labs)» → выгружает CSV/XLSX с колонками К1–К6, флагом эскалации, сутью — один в один как их текущий файл. Это снимает главное возражение покупателя: «А как мы это передадим юристам/бухгалтерии?»

### 10. **Связь с внутренней базой знаний** (Roadmap)
«У нас уже был похожий случай в 2024 с ФЗ № N — вот как мы его решили, вот документы». Для хакатона — мок, для пилота — реальная интеграция.

## ⚠️ Важное предостережение про фокус

В установке дня 2 был анти-паттерн: *«собирать всё, что просили, вместо одного сквозного сценария»*. У нас хакатон, и **сильнее 10 полуработающих фич будет 1 безупречный сквозной сценарий**.

### Мой совет: сфокусируйтесь на ОДНОМ wow-моменте для Demo Day

**Сценарий-кандидат №1: «Lifecycle НПА»**
1. Специалист заходит утром
2. Видит алерт: «Карточка №23: стадия изменилась Проект → Действует с 01.09»
3. Открывает карточку → видит timeline, саммари, привязку к продуктам GS Labs
4. Видит блок «Рекомендуемые действия» с чек-листом
5. Подтверждает в один клик → уходит алерт руководителю
6. Кнопка «Экспорт в Excel» → файл ложится в их текущий реестр

**Сценарий-кандидат №2: «Предотвращённый штраф»**
1. Система ловит карточку №33 (ФАС vs Apple, штраф до 4 млрд ₽)
2. Автоматически привязывает к продуктам GS Labs (DRM, CAS)
3. Алерт GR: «Риск для наших DRM-систем, аналогичные требования могут прийти к нам»
4. GR готовит превентивный план → руководитель видит на матрице рисков красную ячейку, которая стала жёлтой

Я бы брал **сценарий №1** — он показывает весь цикл продукта и привязан к их Excel-реестру (который куратор дал как референс). Сценарий №2 сильнее эмоционально, но требует больше данных.
