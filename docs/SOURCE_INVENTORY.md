## 2. Intake перед разработкой адаптера

Для каждого источника нужно заполнить:

- [ ] canonical name и окончательный внутренний `source_id`;
- [ ] владелец/публичность источника;
- [ ] допустимый способ доступа;
- [ ] официальный RSS/API или стабильная страница списка;
- [ ] доступ к полному тексту, датам и canonical URL;
- [ ] внешний уникальный ID записи;
- [ ] частота обновления и разумный rate limit;
- [ ] правила пагинации и глубина истории;
- [ ] обработка удаления/редактирования исходной записи;
- [ ] offline fixture для тестов и demo fallback;
- [ ] минимум один parser test на сохранённом ответе;
- [ ] маркировка официальности для lifecycle НПА.

## 3. Стратегия Telegram

**Факт:** публичная ссылка `t.me/<channel>` сама по себе не определяет способ
массового получения истории и не даёт разрешения использовать пользовательскую
сессию или секреты.

Порядок:

1. Для demo использовать обезличенный сохранённый export/archive и тип
   `telegram_archive`.
2. Для live определить согласованный доступ: официальный bot/client API либо другой
   разрешённый механизм.
3. API ID/hash, session и иные секреты брать только из окружения и не коммитить.
4. В качестве `external_id` сохранять устойчивый ID сообщения.
5. Canonical URL строить как ссылку на конкретное сообщение, если она доступна.
6. Хранить исходные дату, текст и ссылку без добавления фактов.
7. Telegram-сообщение никогда не подтверждает lifecycle НПА без официального URL.

## 4. Стратегия сайтов

Порядок предпочтения:

1. официальный RSS;
2. официальный API;
3. разрешённый HTML list/detail parser;
4. сохранённый fixture/archive для demo.

Для HTML-сбора до реализации проверяются условия доступа и технические ограничения.
Adapter должен иметь ограничение частоты, timeout, понятный User-Agent, повтор только
для временных ошибок и сохранённый fixture для теста без сети.

Если у сайта нет RSS, текущий enum `SourceType` не содержит отдельного типа `website`
или `html`. Это контрактный вопрос; нельзя молча записывать HTML-adapter как RSS.

## 5. Общий результат collector

Любой adapter должен вернуть одинаковую внутреннюю структуру:

```json
{
  "source_id": "tg-cit-gov",
  "external_id": "stable-source-item-id",
  "title": "Заголовок или короткая первая строка",
  "original_url": "https://source.example/item",
  "published_at": "2026-09-04T08:00:00Z",
  "content": "Исходный нормализованный текст"
}
```

После adapter данные проходят общие normalize, hash и dedup; source-specific код не
должен выполнять LLM-анализ или рассчитывать приоритет.

## 6. Definition of Done одного источника

- источник прошёл intake;
- способ доступа согласован и не требует коммита секретов;
- есть один live adapter либо явно обозначенный archive-only режим;
- есть сохранённый fixture и parser unit-test;
- повторный сбор не создаёт дубли;
- ошибка обновляет `last_error`, но не ломает сбор других источников;
- публикация содержит исходную дату, canonical URL и content hash;
- статус официальности не выводится только из названия канала;
- источник включён в seed лишь через отдельное согласованное изменение контекста.
