# RegRadar: воспроизводимый изолированный E2E-сценарий

## Назначение

Этот документ описывает только автоматическую проверку интерфейса. Синтетические
fixtures не являются рабочими данными и никогда не загружаются в `.local/live.sqlite3`.
Обычный локальный и серверный запуск читают только реально собранные или вручную
добавленные материалы.

## Автоматический E2E

Из корня репозитория:

```bash
npm --prefix frontend run e2e
```

Для диагностики с видимым Chromium:

```bash
npm --prefix frontend run e2e:headed
```

Runner:

1. проверяет, что порты `8000` и `5173` свободны;
2. создаёт уникальный временный каталог;
3. вызывает `tests/seed_test_data.py` и наполняет только временную SQLite;
4. запускает FastAPI с этой БД и Vite с
   `VITE_API_BASE_URL=http://127.0.0.1:8000`;
5. выполняет Playwright-сценарии;
6. в `finally` завершает процессы и удаляет временную БД.

Тестовый набор проверяет фильтры, карточку публикации, версии AI-анализа,
человеческое решение, объединение первоисточников, досье нормативного документа,
lifecycle event, отчёт и Telegram-настройки. Replay в этом контуре — заранее
сохранённый тестовый результат, а не вызов live LLM.

## Ручной тест настоящих данных

Рабочая SQLite создаётся и синхронизируется только с каталогом реальных источников:

```bash
PYTHONPATH=. .venv/bin/python scripts/bootstrap_server_data.py --db .local/live.sqlite3
export HACK_DATABASE_URL="sqlite:///$PWD/.local/live.sqlite3"
PYTHONPATH=. .venv/bin/uvicorn backend.app.main:app --host 127.0.0.1 --port 8000
```

Во втором терминале:

```bash
VITE_API_BASE_URL=http://127.0.0.1:8000 npm --prefix frontend run dev -- --host 127.0.0.1
```

Откройте `http://127.0.0.1:5173/feed`. Публичного endpoint для импорта
синтетических данных нет; MSW не запускается автоматически.

## Инварианты

- Финальный приоритет назначает специалист; AI только предлагает.
- Смысловые дубли не объединяются без решения человека.
- Стадия нормативного документа подтверждается только официальным источником.
- Тестовые fixtures и рабочая БД не смешиваются.
