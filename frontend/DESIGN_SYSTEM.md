# Дизайн-система frontend

Статус: действующая инструкция для всех новых и изменяемых экранов `frontend/`.

Этот документ фиксирует визуальный язык аналитического центра Insight. При
разработке новых функций нужно расширять существующую систему, а не создавать
для каждого экрана отдельный стиль. Визуальный ориентир — технологичный
editorial-продукт с крупной типографикой, спокойной геометрией и умеренной
интерактивностью.

## 1. Основные принципы

1. Содержание важнее декора: пользователь должен быстро увидеть сигнал,
   источник, категорию, приоритет и статус проверки.
2. Иерархия строится размером, контрастом и свободным пространством. Тяжёлые
   тени, градиенты ради украшения и плотные панели не используются.
3. Светлый холодный фон объединяет продукт; белые, чёрные и синие поверхности
   создают акценты.
4. Интерактивные эффекты помогают понять действие и состояние, но не мешают
   чтению и нативной прокрутке.
5. Desktop, tablet и mobile считаются равноправными состояниями интерфейса.
6. Дизайн не должен менять продуктовую семантику, API-модели или полномочия
   пользователя.

## 2. Источник истины

- Глобальные токены и текущие паттерны: `src/index.css`.
- Каркас приложения и навигация: `src/app/App.tsx`.
- Анимация заголовков: `src/shared/RevealText.tsx`.
- Интерактивная сцена и её fallback: `src/shared/HeroVisual.tsx`.
- Состояния loading/error/empty: `src/shared/PageState.tsx`.

Перед созданием нового компонента проверь, нельзя ли переиспользовать один из
этих паттернов. Если новый паттерн повторяется на двух и более экранах, вынеси
его в `src/shared/` и опиши здесь.

## 3. Цветовые токены

Используй CSS variables, не размножай близкие hex-значения внутри компонентов.

| Токен | Значение | Назначение |
|---|---:|---|
| `--background` | `#F1F2F8` | холодный фон приложения |
| `--surface` | `#FFFFFF` | карточки и основные светлые панели |
| `--foreground` | `#090A0D` | основной текст и чёрные действия |
| `--muted` | `#686B75` | метаданные и вторичный текст |
| `--accent` | `#1535D2` | основной синий акцент |
| `--accent-bright` | `#2348FF` | активные и динамические акценты |
| `--dark-surface` | `#111218` | AI-панели и визуальные сцены |
| `--border` | `rgba(9, 10, 13, 0.12)` | тонкие разделители и контуры |
| `--soft-blue` | `#E8EBFF` | мягкий синий фон статусов |
| `--warm-alert` | `#D34C32` | ошибки и действительно опасные состояния |

Новый цвет допустим, только если существующие токены не передают нужную
семантику. В этом случае сначала добавь именованный токен в `:root`.

## 4. Типографика

Базовый стек:

```css
font-family: "Aeonik", "Manrope", "Inter", "Helvetica Neue", Arial, sans-serif;
```

Aeonik можно использовать только при наличии лицензированных файлов в проекте.
Не загружай шрифт с сайтов-референсов. Подключение Aeonik в будущем не должно
требовать изменения компонентов.

- Основные заголовки: weight `400`, line-height `0.95–1.05`, отрицательный
  letter-spacing, адаптивный размер через `clamp()`.
- Заголовки hero могут достигать `7.9rem` на широком экране.
- Заголовки обычных страниц должны оставаться компактнее hero.
- Eyebrow, метаданные и статусы: `10–13px`, uppercase, letter-spacing
  `0.05–0.14em`.
- Основной текст: примерно `15–18px`, line-height `1.5–1.75`.
- Не используй больше трёх визуально различимых насыщенностей на одном экране.
- Для многострочного появления заголовков используй `RevealText`, передавая
  осмысленные строки, а не разбивая текст на отдельные буквы.

## 5. Сетка и пространство

- Максимальная ширина основного контейнера: `1440px`.
- Внешние поля desktop: `56px`; tablet: `32px`; mobile: `16px`.
- Основная сетка карточек: 12 колонок с gap `16px`.
- Hero и заголовочные зоны должны иметь достаточно воздуха; не сокращай их
  высоту ради размещения большего числа элементов above the fold.
- Крупные поверхности: radius `24–30px`.
- Малые панели и уведомления: radius `18–24px`.
- Pills и круглые действия: `border-radius: 999px` или `50%`.
- Границы тонкие, обычно `1px solid var(--border)`.
- Тени допустимы только для отделения плавающей навигации; карточки строятся без
  заметных теней.

## 6. Компонентные паттерны

### Шапка и навигация

- На desktop шапка состоит из бренда, краткого описания продукта и действий.
- Основные пять разделов всегда доступны в pill-навигации.
- Активный маршрут обозначается синим фоном и белым текстом.
- На узких экранах навигация может прокручиваться горизонтально, но не должна
  увеличивать ширину документа.
- Не прячь основную навигацию только за hover или недоступным меню.

### Заголовок страницы

- Используй `.page-heading` для внутренних экранов.
- Порядок: eyebrow → `h1` → пояснение → при необходимости одна metric/stage
  карточка.
- На mobile заголовок и метрика складываются в одну колонку.

### Карточки

- Карточка должна целиком вести к целевому материалу, если у неё одно основное
  действие.
- Верхний уровень информации: индекс или метаданные, затем заголовок, затем
  статусы и теги.
- Hover: лёгкий scale/translate, изменение фона, движение стрелки. Не допускай
  layout shift.
- На touch-устройствах содержание и действие должны быть понятны без hover.

### Статусы и pills

- Статус всегда содержит текст; цвет не является единственным способом передачи
  смысла.
- Синий — активное или информационное состояние.
- Тёплый красный — ошибка или высокий риск, но не обычный декоративный акцент.
- Pills используют uppercase и короткую подпись.

### AI-анализ

- AI-анализ визуально отделяется тёмной или синей поверхностью.
- Предложенный AI-приоритет нельзя оформлять как финальное решение специалиста.
- Всегда сохраняй явную маркировку `AI`, номер версии, неопределённость и
  необходимость проверки, если эти поля доступны.

### Loading, error и empty

- Используй `PageState`, не создавай уникальную заглушку для каждого экрана.
- Loading не должен менять геометрию страницы после получения данных.
- Error должен иметь `role="alert"`; остальные состояния — `role="status"`.
- Текст состояния должен объяснять, что происходит, без технического жаргона.

## 7. Анимация

Базовый easing:

```css
--ease-out: cubic-bezier(0.22, 1, 0.36, 1);
```

- Переход маршрута: fade + translate, `300–500ms`.
- Reveal текста: `600–900ms`, stagger `30–60ms`.
- Hover карточки или стрелки: `300–450ms`.
- Scroll-driven эффекты не перехватывают и не блокируют нативный scroll.
- Не запускай React state update на каждом кадре. Кадровая анимация живёт внутри
  canvas или Web Animations/CSS слоя.
- Не анимируй одновременно большое число декоративных свойств, влияющих на
  layout.

Каждый новый motion-паттерн обязан иметь состояние для
`prefers-reduced-motion: reduce`. В нём убираются parallax, follower, бесконечные
циклы и scroll-driven transform; допустим короткий простой fade.

## 8. 3D и декоративная графика

- Текущая процедурная WebGL-сцена загружается лениво через `React.lazy`.
- Не добавляй внешние модели, изображения или ассеты сайта-референса.
- Для новой сцены сначала оцени, можно ли расширить существующий WebGL/CSS слой
  без тяжёлой зависимости.
- Device pixel ratio ограничивается значением `2`, на mobile — `1.5`.
- На mobile уменьшается число объектов и вычислительная сложность.
- Animation loop останавливается при скрытии вкладки.
- При отсутствии WebGL обязательно отображается статичный fallback.
- Cursor follower разрешён только внутри декоративной области; обычные элементы
  сохраняют стандартный курсор и поведение.

## 9. Адаптивность

Минимальные контрольные размеры:

- `1440 × 900` — основной desktop;
- `1024 × 768` — tablet/небольшой desktop;
- `390 × 844` — mobile.

На mobile:

- карточки переходят в одну колонку;
- текст не выходит за viewport и не обрезается;
- `documentElement.scrollWidth` не превышает `clientWidth`;
- интерактивность не зависит от hover;
- заголовки уменьшаются отдельно от desktop hero;
- внешние поля остаются не меньше `16px`.

Не исправляй overflow только через `overflow-x: hidden`: сначала найди элемент,
который расширяет документ, и исправь его размеры, `min-width` или перенос текста.

## 10. Доступность

- Используй семантические `header`, `nav`, `main`, `section`, `article`, списки и
  корректную иерархию заголовков.
- Все маршруты и основные действия доступны с клавиатуры.
- Видимый `:focus-visible` обязателен.
- Декоративные элементы получают `aria-hidden="true"`.
- Canvas с содержательным визуальным смыслом получает `role="img"` и понятный
  `aria-label`; его fallback не должен дублироваться скринридером.
- Ссылки не маскируются под неинтерактивный текст.
- Проверяй контраст текста и не передавай статус только цветом.

## 11. Продуктовые и технические ограничения

Визуальная задача не даёт права менять архитектуру продукта.

- Сохраняй React Router, существующие маршруты, API-клиент и MSW.
- Страницы не вызывают `fetch` напрямую.
- Не меняй вручную `src/shared/api/schema.d.ts`.
- Не подменяй fixtures новой моделью данных.
- Не создавай неутверждённые API endpoints.
- Не добавляй CRUD, фильтры или редактирование без отдельной продуктовой задачи.
- AI-анализ и решение специалиста остаются раздельными.
- Lifecycle НПА остаётся append-only.
- Не добавляй тяжёлую UI- или animation-библиотеку без обоснованной необходимости.

## 12. Чек-лист готовности

Перед завершением frontend-задачи проверь:

- экран использует существующие токены и паттерны;
- есть loading, error и empty states там, где загружаются данные;
- фокус видим, действия доступны с клавиатуры;
- hover не является единственным способом взаимодействия;
- `prefers-reduced-motion` сохраняет рабочий интерфейс;
- нет layout shift и горизонтального overflow;
- проверены `1440 × 900`, `1024 × 768`, `390 × 844`;
- прямые переходы по URL работают с MSW без backend;
- консоль браузера не содержит ошибок;
- выполнены команды:

```bash
npm --prefix frontend run generate:api
npm --prefix frontend run typecheck
npm --prefix frontend run lint
npm --prefix frontend run test -- --run
npm --prefix frontend run build
```

Если задача сознательно отступает от этой системы, отступление и его причина
должны быть явно указаны в описании задачи и итоговом отчёте.
