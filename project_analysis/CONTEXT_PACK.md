## 1. Проблема одной фразой + чья это работа
**Ситуация:** GR/PR-специалисты GS Labs вручную держат «Реестр оценки влияния НПА
и отраслевых событий» в Excel: сбор из десятков источников, сути, баллы К1–К6,
флаги эскалации, переносы карточек — обновляется неделями, ежедневная повестка
разбирается часами.
**Хочу:** к 9:00 весь поток (СМИ + НПА + Telegram) собран, саммаризирован,
проскорирован по нашей методике и разложен по приоритетам в одном интерфейсе;
источники и карточки под моим контролем.
**Чтобы:** GR/PR-специалист не пропускал критичные НПА (штрафы/уголовка/
приостановка) и точки роста (льготы/федпроекты), а руководитель получал
дайджест для управленческих решений.

**Чья это работа (JTBD):**
- Подработа (кейс): «собрать дайджест/обновить реестр, не пропустив важное».
- Большая работа (продукт): «вовремя заметить регуляторное/рыночное изменение и
  отреагировать до того, как оно стало риском или упущенной возможностью».
- Делает руками: GR/PR-специалист (носитель проблемы — тот, кто ведёт реестр).
- Платит: директор по коммуникациям/GR. Потребляет результат: руководитель.
- Ту же работу делают: комплаенс, юристы, аналитики, продуктовые команды → продукт.

**Наш скоуп в кейсе:** ядро — GR-контур (НПА + отраслевые новости + методика
К1–К6/Н1–Н4); PR-контур (СМИ/репутация) — тем же конвейером, категории
«репутация/конкуренты/тренды» второй очередью.

## 2. Как делают сейчас и что это стоит (baseline для доказательства ценности)
- Excel-реестр: 46 карточек за август, сквозная нумерация, ручные ячейки (стадия,
  баллы, флаг, действия, сроки), легенда «ТРЕБУЕТ ОБНОВЛЕНИЯ», версия файла от
  28.08 за период 03–28.08 → обновление эпизодическое, не realtime.
- Ежедневный мониторинг вручную: 30+ источников (СМИ, regulation.gov.ru, sozd.duma.gov.ru,
  TG-каналы, дайджесты ИРИ/ЭБР); утренний разбор — часы (уточнить в интервью).
- Плюс платные мониторинги у рынка (от ~35 т.р./мес) — дают охват, не дают дайджест.
- Цена боли: часы специалиста ежедневно; пропуски = регуляторные/репутационные риски
  (самая дорогая строка); задержка реакции руководителя.
- Эффективность измеряется «по отрицанию» (нет скандала = работает) → предлагаем
  метрики: время утреннего разбора, % пропусков критичного, время реакции.

## 5. Аналоги (3–5) + чем отличаемся + Why now
1. **Медиалогия** — охват/измерения PR. Мы: готовый дайджест + скоринг по методике.
2. **СКАН-Интерфакс** — алерты. Мы: ИИ-аналитик «что это значит для нас» + human-in-the-loop.
3. **КонсультантПлюс/Гарант** — полнота НПА. Мы: «что значит» + приоритет + СМИ/TG в одном потоке.
4. **Meltwater** — есть AI-саммари, но глобальный, дорого, слабо в РУ-регуляторике.
   Мы: РУ-специфика, on-prem/РУ-LLM, цена для команды.
5. **Excel-реестр (текущий процесс)** — методика отличная, исполнение ручное и долгое.
   Мы: методика сохранена, ручной труд убран, мониторинг непрерывный.
**Почему кейсодатель не пользуется готовым:** мониторинги не дают дайджеста и не
говорят «насколько это важно для GS Labs»; юрбазы не дают отраслевого контекста.

**Why now (что стало возможно за последний год):**
- LLM-саммаризация и извлечение сущностей на русском стали рабочими, включая
  открытые модели для on-prem (требование регулируемых компаний);
- стоимость инференса упала: сотни документов/день — копейки;
- tool calling / MCP — стандартное подключение источников без кастомных интеграций;
- тренд подтверждён лидером: Meltwater за последний год ввёл AI-саммари.

## 6. Гипотезы (формат: если → то → потому что + метрика + ожидание)
**Продуктовые:**
- H1. Если специалист получает утреннюю ленту с готовыми саммари и приоритетами,
  то разбор суточной повестки падает с часов до 10–15 минут, потому что сейчас время
  уходит на просмотр источников и переписывание сутей. Метрика: время утреннего цикла
  (наблюдение/демо). Ожидание: ≤15 мин (ориентир куратора).
- H2. Lifecycle-трекинг НПА + алерты при смене стадии; специалист подтверждает переоценку в один клик.
- H3. Если есть режим «дайджест руководителю», то продукт закрывает большую работу
  (своевременная реакция), и покупателем становится директор по коммуникациям/GR.
  Метрика: интервью с покупателем + пилот: дайджест используется ≥2 недель.
- **H4 (RAT — самое рискованное, проверяем первой в день 3):** если ИИ даёт саммари
  и приоритеты, то специалист доверяет им настолько, что работает в режиме валидации,
  а не переписывания, потому что иначе время не экономится и продукт — лишняя прослойка.
  Метрика: % саммари без существенных правок + 0 случаев «критичное→низкое».
  Ожидание: ≥80% и 0.
- H5: явная цена пропуска в карточке (штраф/уголовка) → конверсия в пилот.

**AI-гипотезы:**
- AI1. Саммари 3–5 предложений на русском не содержат фактов вне оригинала.
  Метрика: выборочная ручная проверка 50 материалов. Ожидание: 100% фактологичность.
- AI2. Категоризация по важности ≥80% при 0 «критичное→низкое» на разметке датасета.
- AI3. Обработка одной публикации 10–15 сек на скромном железе; поиск/фильтры <1 сек.
- AI4. Дубли одной новости схлопываются в одну карточку (100% на тестовых парах).

**Приоритизация гипотез:** RICE — черновик через n8n-пайплайн эксперта; выбор RAT —
только людьми (не делегируем).

## 7. Команда, роли и ИИ в процессе
- Роли: продукт (пак, питч, интервью) / ML (саммаризация+eval) / backend (сбор, API,
  CRUD) / frontend (дашборд) / демо.
- ИИ в процессе: этот пак → в CLAUDE.md; n8n-пайплайн эксперта
  (AI_Product_Discovery.json) — черновики сегментов/ICP/pain map/JTBD/гипотез/RICE за
  20–30 мин; LLM — конспекты транскриптов интервью, итерации промптов с eval-скриптом.
- Регистрация: email + пароль + роль (PR/GR/Руководитель). Ролевой
  профиль конфигурирует стартовый набор источников, категорий и алертов
  в едином интерфейсе. Интерфейс один — конфигурации разные.
- **Не делегируем ИИ:** разговор с носителем проблемы; подтверждение болей живыми
  цитатами; выбор самого рискованного предположения; решение, что проверяем;
  продуктовую метрику «помогло ли человеку»; честность про неподтверждённое.
- Синтетические интервью (пайплайн) — генератор вопросов, НЕ доказательство.
